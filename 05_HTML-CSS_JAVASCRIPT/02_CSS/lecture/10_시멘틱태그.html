시맨틱 태그

시맨틱(semantic)은 '의미를 가진'이라는 뜻이다. div와 span은 아무 의미가 없는 중립적인 상자지만, header·nav·footer 같은 태그는 그 영역이 무슨 역할인지를 이름 자체로 알려준다.

1. 태그별 의미와 용도

태그 역할
header 머리말 영역. 로고, 검색창, 상단 메뉴(nav)가 주로 들어간다.
nav 다른 페이지로 이동하는 링크 묶음. header 안이나 사이드에 위치한다.
main 페이지의 핵심 본문. 한 페이지에 하나만 쓴다.
section 주제별로 묶은 영역. 보통 제목(h1~h6)을 동반한다.
article 그 자체로 독립적으로 배포될 수 있는 콘텐츠 단위. 게시글, 댓글, 상품 카드 등.
aside 본문과 직접 관련 없는 부가 영역. 광고, 링크 모음, 사이드바.
footer 꼬리말. 회사 정보, 저작권, 연락처.
section과 article이 가장 헷갈린다. 기준은 "떼어내도 말이 되는가"다. 블로그 글 하나는 떼어내도 완결된 글이므로 article, "인기 게시글 목록"처럼 묶음의 성격을 나타내는 영역은 section이다. article 안에 section이, section 안에 article이 들어가는 것 모두 가능하다.

4. 시맨틱 태그를 쓰는 이유

① 검색 엔진이 어디가 본문이고 어디가 광고인지 구분할 수 있다.
② 화면 낭독기가 시각장애인 사용자에게 "여기부터 본문입니다"라고 안내할 수 있다. div는 아무 정보도 주지 못한다.
③ 코드를 읽는 사람이 구조를 훨씬 빨리 파악한다. div가 수십 개 중첩된 코드와 header/main/footer로 나뉜 코드의 차이는 크다.
참고. 시맨틱 태그는 기본적으로 block 레벨 요소일 뿐, 특별한 스타일이 붙어 있지는 않다. 배치는 결국 CSS(flex·grid)로 해야 한다.
