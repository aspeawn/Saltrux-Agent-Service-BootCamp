# 실습 코드 검토

학생이 문제를 다 풀었다고 할 때 쓴다.

## 절차

1. 학생이 작성한 파일을 읽는다. 별도 CSS 파일이 있으면 그것도 같이 읽는다.

2. 문제 파일의 `[완성 조건]`(99번은 `[요구 사항]`)을 하나씩 짚으며 표로 정리한다.

   | 완성 조건 | 충족 | 비고 |
   |---|---|---|

3. **미충족 항목은 무엇이 잘못됐는지 먼저 말한다.**
   고친 코드는 학생이 원한다고 말할 때만 준다.
   "여기가 틀렸으니 이렇게 고치세요"가 아니라
   "이 부분이 왜 그렇게 동작하는지"를 먼저 설명한다.

4. 완성 조건을 다 지켰다면 그다음에 개선점을 말한다.

   - **`!important`를 썼는가.** 썼다면 선택자로 푸는 방법을 같이 찾는다.
   - **축약형과 개별 속성이 충돌하는가.**
     `margin-top`을 쓴 뒤 `margin`을 쓰면 앞의 것이 암묵적으로 덮인다.
   - **같은 속성을 한 규칙에서 여러 번 선언했는가.** 마지막 것만 적용된다.
   - **선택자 우선순위가 불필요하게 높은가.** `id`나 긴 후손 선택자 대신 `class`로 되는지 본다.
   - 박스가 밀리는 문제라면 `box-sizing: border-box`가 있는지 본다.
   - 이미지에 `max-width: 100%`가 있는지 본다. 없으면 화면을 뚫고 나간다.

## 화면으로 확인시키기

**코드를 눈으로만 보지 말고 학생에게 브라우저로 열어 보게 한다.**
CSS는 코드가 그럴듯해도 화면이 다를 수 있다.

- 레이아웃 문제는 F12 - `Elements`에서 요소를 골라 박스 모델 그림을 보게 한다.
- 반응형 항목이 있으면 **창 너비를 직접 줄였다 늘려** 확인하게 한다.

## 진단 우선

이 과정의 목표는 코드를 받는 것이 아니라 **문제를 짚어내는 능력**을 기르는 것이다.
고친 코드보다 **원인 설명**이 먼저다.

## 금지

- `exercises_answer/`와 비교하지 않는다.
  모범 답안은 하나의 풀이일 뿐이고, 학생의 다른 풀이도 맞을 수 있다.
  판단 기준은 언제나 문제 파일의 `[완성 조건]`이다.
  학생이 모범 답안을 보고 싶어 하면 "항복"이라고 말하면 된다고 알려준다. (hint 스킬이 받는다)
- 학생이 쓰지 않은 코드를 마음대로 추가하지 않는다.
- Bootstrap, Tailwind 같은 프레임워크로 고쳐 주지 않는다. 순수 CSS로 푼다.
