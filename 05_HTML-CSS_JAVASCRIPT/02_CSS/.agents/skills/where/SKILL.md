# 자료 위치 찾기

학생이 개념이나 오류 메시지를 대면 **수업 자료의 어느 파일 몇 번째 줄을 봐야 하는지** 짚어 준다.

## 절차

1. **`REVIEW.md`를 먼저 본다.**
   학습 목표가 파일별로 정리돼 있어 개념에서 파일로 가는 매핑이 여기 있다.
   제목에 파일명이 붙어 있다. 예: `## 3. 레이아웃 (`7-1`~`7-6`)`

2. **그 파일 안에서 실제 위치를 찾는다.**
   속성 이름이나 선택자로 검색해 줄 번호를 확인한다.
   **추측하지 않는다.** 파일을 열어 확인한 줄 번호만 말한다.

3. **이렇게 답한다.**

   > `7-5_flex레이아웃.html` 38행 - `justify-content`로 가로 정렬을 정하는 예제가 있다.
   > `REVIEW.md`의 "3. 레이아웃" 항목도 같이 보면 좋다.

4. 여러 곳에 흩어져 있으면 **가장 기본이 되는 곳 하나를 먼저** 짚고, 나머지는 목록으로만 준다.

## 코드를 붙여넣지 않는다

**위치만 알려주고 내용은 학생이 직접 열어 보게 한다.**

실습 문제를 풀다가 물어보는 경우가 많다. 여기서 예제 코드를 그대로 옮겨 오면
사실상 답을 주는 셈이 된다. 한 줄짜리 요약은 괜찮지만 코드 블록은 붙여넣지 않는다.

학생이 "그냥 코드 보여줘"라고 하면, 파일을 열어 보라고 안내하고
그래도 막히면 "힌트 줘"라고 말하면 된다고 알려준다.

## 오류 메시지로도 찾는다

학생이 브라우저 콘솔의 오류를 그대로 붙여넣으면 그것으로 찾는다.
`REVIEW.md`에는 오류 메시지가 항목으로 적혀 있는 경우가 있다.

## 못 찾았을 때

수업 자료에 없는 내용이면 **없다고 말한다.** 그럴듯한 파일명을 지어내지 않는다.

아직 배우지 않은 내용이면 몇 번 파일에서 다루는지만 알려주고, 지금은 몰라도 된다고 말한다.

## 금지

- `exercises_answer/`는 검색 대상이 아니다.
- 다른 실습 문제의 답이 될 만한 코드를 흘리지 않는다.
