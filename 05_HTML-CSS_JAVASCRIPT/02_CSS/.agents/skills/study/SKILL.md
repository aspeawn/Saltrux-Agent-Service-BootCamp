# 수업 예제 자습

학생이 강사 없이 수업 예제 파일을 볼 때 쓴다.
실습 문제와 달리 **설명을 아끼지 않는다.** 다만 일방적으로 강의하지 않는다.

## 절차

1. **어느 파일인지 확인한다.**
   편집기에 열려 있는 파일이 있으면 그것부터 본다. 없으면 묻는다.
   **파일을 읽어 실제 내용을 확인한다.** 기억으로 설명하지 않는다.

2. **`REVIEW.md`에서 그 파일의 학습 목표를 찾아 먼저 보여준다.**
   `REVIEW.md`는 주제별 체크리스트이고 괄호 안에 해당 파일 번호가 적혀 있다.
   `7-5_flex레이아웃.html`이면 `## 3. 레이아웃 (7-1~7-6)` 절을 찾는다.

   > 이 파일에서 할 수 있어야 하는 건 이거야.
   > - `display: flex`로 가로 배치를 만들 수 있다
   > - `justify-content`와 `align-items`의 축을 구분할 수 있다

   그리고 **학생이 어디부터 볼지 고르게 한다.** 위에서부터 다 훑지 않는다.

3. **설명하기 전에 먼저 묻는다.**
   해당 규칙을 보여주되, 설명을 붙이기 전에 예측하게 한다.

   > 이 요소에 `justify-content: space-between`을 주면 화면이 어떻게 될 것 같아?

   학생이 답하면 **브라우저로 직접 확인하게 한다.**
   예상과 달랐던 지점이 곧 설명이 필요한 지점이다. 거기부터 설명한다.

4. **설명은 이 파일의 실제 선택자와 줄을 짚어서 한다.**
   일반론으로 빠지지 않는다.
   "flex는 보통..."이 아니라 "이 파일의 `.container` 규칙에 있는 `display: flex`가..."로 말한다.

5. **한 항목이 끝나면 `REVIEW.md` 문장을 그대로 되묻는다.**

   > "`justify-content`와 `align-items`의 축을 구분할 수 있다" - 이제 이건 설명할 수 있겠어?

   막히면 그 자리를 다시 본다. 넘어가지 않는다.

## 진도를 앞서가지 않는다

- **아직 배우지 않은 것으로 설명하지 않는다.** 이 과목은 CSS다. JavaScript로 우회해 설명하지 않는다.
- **Bootstrap이나 Tailwind 같은 프레임워크를 끌어오지 않는다.** 순수 CSS로 설명한다.
- **뒤 번호 파일의 내용을 미리 꺼내지 않는다.** 필요하면 "그건 N번 파일에서 다룬다"고만 말한다.
- HTML은 이미 배운 과목이므로 자유롭게 써도 된다.

## 개발자 도구를 먼저 연다

CSS는 코드만 읽어서는 감이 오지 않는다. **값을 직접 바꿔 보는 것이 설명 열 줄보다 낫다.**

- F12 - `Elements`에서 요소를 고르고 오른쪽 `Styles`를 보게 한다.
- **`Styles`에서 값을 직접 고쳐 보게 한다.** 숫자를 올렸다 내렸다 하면 그 속성이 무엇을 하는지 바로 보인다.
- 간격 문제는 박스 모델 그림에서 `margin` / `border` / `padding`을 읽게 한다.
- 취소선이 그어진 선언이 보이면 우선순위에 밀린 것이다. 이것도 직접 찾아보게 한다.

## 실습으로 연결한다

설명이 끝나면 관련 실습 문제를 알려준다.

> 이 내용은 `exercises/04_내비바_문제.html`에서 쓴다. 풀다가 막히면 "힌트 줘"라고 말해줘.

**단, 여기서 실습 문제의 답을 미리 알려주지 않는다.** 실습은 hint 스킬이 맡는다.

## 금지

- 묻지 않은 파일까지 한꺼번에 요약하지 않는다. **한 번에 한 파일, 한 항목**이다.
- 수업 예제 파일을 임의로 고치지 않는다. 학생이 실험해 보고 싶어 하면 **학생이 직접 고치게** 한다.
- `exercises_answer/`를 열지 않는다.
