# 실습 코드 검토

학생이 문제를 다 풀었다고 할 때 쓴다.

## 절차

1. 학생이 작성한 파일을 읽는다.

2. 문제 파일의 `[완성 조건]`을 하나씩 짚으며 표로 정리한다.

   | 완성 조건 | 충족 | 비고 |
   |---|---|---|

3. **미충족 항목은 무엇이 잘못됐는지 먼저 말한다.**
   고친 코드는 학생이 원한다고 말할 때만 준다.
   "여기가 틀렸으니 이렇게 고치세요"가 아니라
   "이 부분이 왜 그렇게 동작하는지"를 먼저 설명한다.

4. 완성 조건을 다 지켰다면 그다음에 개선점을 말한다.

   - 접근성 : `img`의 `alt`, `iframe`의 `title`, 폼의 `label`
   - 의미에 맞는 태그를 썼는지 (`div`로만 처리하지 않았는지)
   - 닫는 태그 누락, 중첩 오류
   - 표라면 `th` / `scope`, 폼이라면 `label`의 `for`와 입력 요소의 `id` 연결

## 브라우저로 확인시키기

코드를 눈으로만 보지 말고 **학생에게 브라우저로 열어 보게 한다.**
특히 표·폼 문제는 화면에서 증상이 바로 보인다.

## 금지

- `exercises_answer/`와 비교하지 않는다.
  모범 답안은 하나의 풀이일 뿐이고, 학생의 다른 풀이도 맞을 수 있다.
  판단 기준은 언제나 문제 파일의 `[완성 조건]`이다.
  학생이 모범 답안을 보고 싶어 하면 "항복"이라고 말하면 된다고 알려준다. (hint 스킬이 받는다)
- 학생이 쓰지 않은 코드를 마음대로 추가하지 않는다.
