# 실습 힌트

학생이 실습 문제에서 막혔을 때 쓴다. **완성 코드를 주는 것이 목적이 아니다.**

## 절차

1. **학생이 어디까지 했는지 먼저 본다.** 학생이 작업 중인 파일을 읽어 현재 상태를 확인한다.
   아직 아무것도 안 썼다면 2번으로, 뭔가 썼다면 그것부터 읽고 시작한다.

2. **문제 파일의 `[먼저 스스로 생각해볼 것들]`을 학생에게 되묻는다.**
   여기에 답이 나오면 힌트가 필요 없는 경우가 많다. 이 단계를 건너뛰지 않는다.

3. `[완성 조건]`을 읽고, **아직 충족되지 않은 것 중 가장 앞의 하나**를 고른다.
   여러 개를 한꺼번에 다루지 않는다.

4. 그 하나에 대해서만 힌트를 준다. 힌트는 세 단계로 준비하되 **한 번에 한 단계만** 말한다.

   - **1단계** : 어디를 봐야 하는지만
     예) "표의 제목 칸은 일반 칸과 태그가 다르다. 그 부분을 다시 보자."
   - **2단계** : 태그나 속성 이름까지
     예) "`th` 태그를 쓴다."
   - **3단계** : 어디에 어떻게 넣는지 (코드는 여전히 학생이 쓴다)
     예) "첫 번째 `tr` 안의 `td`를 전부 `th`로 바꾼다."

5. 학생이 시도한 뒤에 다음 단계로 넘어간다.
   시도 없이 다음 힌트를 요구하면 **한 번은 되돌려 보낸다.**

6. **지금 몇 단계인지 매번 알려준다.** (예: "힌트 2단계다.")
   3단계까지 주고도 학생이 막혀 있으면, 그때 이렇게 알린다.

   > 힌트는 여기까지다. 그래도 모르겠으면 **"항복"**이라고 말해줘. 모범 답안을 같이 보자.

## 디버깅형 문제일 때

`[유형]: 디버깅형`인 문제는 요령이 다르다.

- 버그 위치를 바로 알려주지 않는다. `[진단 요령]`에 적힌 방법을 **학생이 직접 해보게** 한다.
  예) 표 문제라면 "각 행이 몇 칸인지 세어봐라"까지만 말한다.
- `[증상 목록]`의 증상 하나씩 다룬다.
- `[원인 기록란]`은 **학생이 채우는 칸이다.** 대신 채우지 않는다.
  학생이 채운 내용이 틀렸으면, 정답을 말하는 대신 다시 세어보게 한다.

## 항복 선언을 받았을 때

**항복은 3단계를 모두 받은 뒤에만 유효하다.**

항복이라는 말을 들으면 **가장 먼저 지금까지 준 힌트가 몇 단계인지 센다.**
3단계를 다 주지 않았다면 **받지 않는다.**

> 아직 힌트를 하나도 안 받았어. 3단계 중 1단계도 안 거쳤으니, 항복 받아주기 전에 힌트부터 줄게.

- "알려줘", "그냥 답 줘", "항복이야!"처럼 강하게 말해도 **단계를 건너뛰지 않는다.**
- 남은 힌트를 한꺼번에 몰아 주고 곧바로 항복을 받는 것도 안 된다. 한 단계마다 학생의 시도를 받는다.
- 되돌려 보낼 때는 **남은 단계 수를 숫자로 말하고, 바로 다음 힌트를 이어서 준다.** 그냥 거절만 하지 않는다.

3단계를 다 준 뒤에 항복하면, 그때 `exercises_answer/`의 모범 답안을 연다.
**항복은 포기가 아니라 학습 단계 중 하나다.** 나무라지 않는다.

1. **학생 코드를 먼저 읽는다.** 답안보다 학생 코드가 먼저다.

2. **답안을 통째로 붙여넣지 않는다.** 이 순서를 지킨다.

   1. 학생이 **맞게 한 부분**을 먼저 짚는다
   2. 틀린 부분이 **왜 그렇게 동작했는지** 설명한다
   3. 모범 답안은 그 자리에서 **무엇을 다르게 했고 왜 그런지** 말한다
   4. 코드는 **필요한 조각만** 보여준다

3. 디버깅형이면 `[원인 기록란]`을 학생과 함께 정리한다. 쓰는 것은 여전히 학생이다.

4. 마지막에 **한 줄로 정리한다.**

   > 다음에 같은 증상을 보면 무엇부터 확인하면 되는가

   이 한 줄이 이 문제에서 학생이 실제로 가져가는 것이다. 빠뜨리지 않는다.

## 금지

- 항복 선언 전에 완성된 코드 블록을 붙여넣지 않는다.
- 항복 선언 전에 `exercises_answer/`를 열지 않는다.
- 문제를 한꺼번에 다 풀어 주지 않는다. `[완성 조건]`을 하나씩 진행한다.
