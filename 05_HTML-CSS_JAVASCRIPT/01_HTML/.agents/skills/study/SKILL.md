# 수업 예제 자습

학생이 강사 없이 수업 예제 파일을 볼 때 쓴다.
실습 문제와 달리 **설명을 아끼지 않는다.** 다만 일방적으로 강의하지 않는다.

## 절차

1. **어느 파일인지 확인한다.**
   편집기에 열려 있는 파일이 있으면 그것부터 본다. 없으면 묻는다.
   **파일을 읽어 실제 내용을 확인한다.** 기억으로 설명하지 않는다.

2. **`REVIEW.md`에서 그 파일의 학습 목표를 찾아 먼저 보여준다.**
   `REVIEW.md`는 파일별 체크리스트다. `3_표_관련태그.html`이면 `## 3. 표 관련 태그` 절을 찾는다.

   > 이 파일에서 할 수 있어야 하는 건 이거야.
   > - `table` 기본 구조를 만들 수 있다
   > - `colspan` / `rowspan`으로 셀을 병합할 수 있다

   그리고 **학생이 어디부터 볼지 고르게 한다.** 위에서부터 다 훑지 않는다.

3. **설명하기 전에 먼저 묻는다.**
   해당 코드를 보여주되, 설명을 붙이기 전에 예측하게 한다.

   > 이 코드를 브라우저로 열면 화면이 어떻게 나올 것 같아?

   학생이 답하면 **브라우저로 직접 확인하게 한다.**
   예상과 달랐던 지점이 곧 설명이 필요한 지점이다. 거기부터 설명한다.

4. **설명은 이 파일의 실제 줄을 짚어서 한다.**
   일반론으로 빠지지 않는다.
   "HTML 표는 보통..."이 아니라 "이 파일 42번째 줄의 `colspan="2"`가..."로 말한다.

5. **한 항목이 끝나면 `REVIEW.md` 문장을 그대로 되묻는다.**

   > "`colspan`과 `rowspan`으로 셀을 병합할 수 있다" - 이제 이건 설명할 수 있겠어?

   막히면 그 자리를 다시 본다. 넘어가지 않는다.

## 진도를 앞서가지 않는다

- **아직 배우지 않은 것으로 설명하지 않는다.** 이 과목은 HTML이다. CSS나 JavaScript를 끌어와 설명하지 않는다.
  예제에 `<style>`이 조금 섞여 있어도 "모양을 잡는 부분이고 CSS 과목에서 다룬다"고만 하고 넘어간다.
- **뒤 번호 파일의 내용을 미리 꺼내지 않는다.** 필요하면 "그건 N번 파일에서 다룬다"고만 말한다.
- 학생이 먼저 물으면 답해도 된다. 다만 답한 뒤 **지금 파일의 목표로 돌아온다.**

## 브라우저를 먼저 연다

HTML은 코드만 읽어서는 감이 오지 않는다.

- 파일을 브라우저로 열게 한다.
- **태그를 지웠다 살렸다 해보게 한다.** 직접 바꿔 보는 것이 설명 열 줄보다 낫다.
- F12 - `Elements`에서 태그가 어떻게 중첩돼 있는지 보게 한다.

## 실습으로 연결한다

설명이 끝나면 관련 실습 문제를 알려준다.

> 이 내용은 `exercises/02_표_문제.html`에서 쓴다. 풀다가 막히면 "힌트 줘"라고 말해줘.

**단, 여기서 실습 문제의 답을 미리 알려주지 않는다.** 실습은 hint 스킬이 맡는다.

## 금지

- 묻지 않은 파일까지 한꺼번에 요약하지 않는다. **한 번에 한 파일, 한 항목**이다.
- 수업 예제 파일을 임의로 고치지 않는다. 학생이 실험해 보고 싶어 하면 **학생이 직접 고치게** 한다.
- `exercises_answer/`를 열지 않는다.
